# Исправления RPM Attorney Assistant

## Проверка юридических ссылок

- Сверка статьи больше не подтверждается только совпадением номера в любом документе.
- Для полного подтверждения требуется определить нормативный документ и найти в нём указанную статью.
- Если в ссылке указана глава или раздел, этот реквизит также проверяется.
- Ссылки только с номером статьи получают статус «Недостаточно данных для подтверждения».
- Совпадения из других документов показываются отдельно и не засчитываются как подтверждение.
- Номер пункта больше не трактуется как номер статьи.

## Извлечение статей

- Нумерованные контейнеры-разделы в УК и Административном кодексе больше не попадают в список статей как отдельные ложные записи.
- Номер и название раздела сохраняются в метаданных вложенных статей.
- Существующие римские главы ЕПК продолжают распознаваться.

## Интерфейс

- Статусы с недостаточными данными, неподтверждением или несовпадением отображаются как предупреждения, а не как успешная проверка.
- Зелёный статус применяется только к точному статусу «Подтверждено» (или эквивалентам на английском).
- Добавлено отдельное название поля для совпадений в других документах.

## Проверки

Выполнены:
- `npm run check`
- `npm run test:audit`
- `npm run test:parsing` — проверка обработки обычного, fenced и вложенного JSON-ответа ИИ
- синтаксическая проверка встроенного JavaScript в `public/index.html`

## Настройка

1. Установить зависимости: `npm install`
2. Скопировать `.env.example` в `.env`.
3. Заполнить собственные `DATABASE_URL`, `SESSION_SECRET`, `APP_USER`, `APP_PASSWORD` и `GEMINI_API_KEY`.
4. Запустить проверку: `npm run check`
5. Запустить регрессионные тесты аудита: `npm run test:audit`
6. Проверить обработку ответов ИИ: `npm run test:parsing`
7. Запустить приложение: `npm start`

Файл `.env` с секретами в этот архив не включён.
