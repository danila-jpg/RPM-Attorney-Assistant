## Структурированный юридический анализ

- `legal-engine.js` и `server.js` добавляют десять режимов через `/api/attorney-assist` с `format: "structured"`. Существующие режимы сохраняют прежний формат API.
- Сервер проверяет JSON по схеме, делает до двух запросов в пределах 35 секунд и возвращает учёт токенов при наличии метрик. Статусы цитат выставляются только по выбранным сервером записям RPM.
- `public/index.html` показывает результат отдельными блоками, раскрывает запись источника, позволяет перейти в библиотеку и копировать результат. Действие «Сохранить дело» использует существующее хранилище истории, где сохраняется текст анализа.
- `tests/legal-engine.test.mjs` и `tests/workspace-integration.test.mjs` проверяют валидацию, повторный запрос, разделение инструкции и материалов, сверку ссылок и защиту от доступа к архивным копиям интерфейса по HTTP. Gemini подставлен тестовым провайдером.
- Структурированные анализы, доказательства и память CRM ещё требуют отдельного хранения. Не реализованы команды, симулятор, редактор с версиями и DOCX, полная проверка тарифов и безопасности и приёмка всех страниц.

## CRM. Карточки клиентов

- `007_crm_clients.sql` добавляет таблицу и индекс. Миграция включена в `workspace-migrations.js`. Тестовое окружение применяет её дважды в изолированном PGlite. Миграция production не выполнялась.
- `workspace-routes.js`, `public/workspace-clients.js`, `public/workspace-router.js` и `public/index.html` добавляют создание, чтение, изменение, поиск, сортировку, пагинацию и архив клиентов. Запросы ограничены владельцем карточки, в том числе при доступе администратора.
- Интеграционный тест проверяет чтение и изменение чужой карточки, архивирование и отсутствие заметок в списке. Chrome подтвердил рендер структурированного анализа с подставной моделью и создание карточки клиента. Прогон с этими сценариями прошёл 21 из 21 проверок.
- Следующий шаг — дела CRM, участники, ответственные, связи клиентов с делами, доказательства и командные роли. Публикация ожидает выполнения критериев приёмки.

## Каталог подписок

- `subscription-plans.js` возвращает названия восьми стандартных тарифов из серверной конфигурации. Цены и сроки по-прежнему читаются из PostgreSQL. Карточки показывают названия и длительность.
- API создания заказов и продлений принимает `1_day` и сохраняет исторический код `1_days`, на который ссылаются существующие записи. Цены, длительности и ставки комиссий не изменены.
- В изолированном PostgreSQL проверены восемь названий, цены, подмена полей, подтверждение всех восьми продлений, их партнёрские комиссии и отказ при повторном подтверждении. Ставка 7,5% используется только в тестовых данных.
- Форма и API регистрации требуют поле `confirmation`. API ограничивает частоту запросов, проверяет JSON и возвращает общее сообщение при конфликте уникальности. HTTP-тест прошёл путь от нового заказа с промокодом до регистрации, выпуска лицензии и отклонения повторного использования приглашения. Просроченный код дважды отклонён и не создал лицензию.
