# Обновление RPM Attorney Assistant

1. Аудит текущей ветки, маршрутов, схемы, интерфейса и состояния тестов.
2. Общие токены дизайна, адаптивная оболочка и персонализация профиля.
3. Кабинет администратора, управление сессиями, доступ владельца и единая кнопка показа пароля.
4. Нормализация ANSI, каталог по организациям, просмотр, поиск и ссылки на пункты.
5. Обучение по действующим документам, проверка ответов, прогресс и повтор ошибок.
6. Действующая и архивная редакции ЕПК, проверка ссылок и вывод подтверждённых источников.
7. Интеграционные прогоны на изолированной PostgreSQL и браузерная приёмка.
8. Проверка перечня изменений, документация миграций, запуск и подготовка к развёртыванию.

Для проверки использовать отдельную базу, без подключения к production. На Render при запуске приложения автоматически применяются добавочные миграции 002–004. Миграция 001 остаётся предварительным условием для существующей схемы.

## Запуск и подготовка к Render

1. Установите Node.js 22 или новее и выполните `npm ci`.
2. Используйте существующий `.env` для нужной среды. Перечень переменных приведён в `.env.example`. Для разработки укажите отдельную базу или тестовую ветку.
3. Для локального запуска примените `migrations/001_owner_partners_profiles.sql`, если она ещё не применялась, затем миграции 002–004. Миграция 004 добавляет таблицы избранного, прочитанных уведомлений, событий и объявлений. На Render заголовок `X-RPM-Revision` ответа `/api/health` показывает хеш запущенной версии.
4. Выполните `npm run check`, `npm test` и `npm start`. Вход сотрудников находится на `/admin-login`, кабинет на `/admin`, уставы на `/charters`, обучение на `/training`.
5. При будущем развёртывании на Render используйте `npm ci` для сборки и `npm start` для запуска. Настройте переменные через настройки сервиса. GitHub должен содержать `laws.json`, новые HTML в `private/` и SQL в `migrations/`.

Интеграционная проверка использует временные зависимости и изолированный PostgreSQL на WebAssembly. Для её запуска установите зависимости командой `npm install --prefix .workspace-test @electric-sql/pglite playwright-core`. Чтобы включить проверку интерфейса, передайте путь к установленному Chromium через переменную `WORKSPACE_TEST_BROWSER`.

## Импорт

Для проверенного исходника выполните `node scripts/import-rpm-documents.mjs <Desktop> <Downloads>`, указав фактические пути Windows. В предоставленном ЕПК редакции от 20.11.2026 найдено 11 глав, 51 нумерованная статья, 216 пунктов и отдельный ненумерованный раздел «Заключительные положения». Указанное в задании число 52 соответствует количеству статей вместе с этим разделом. Исходный текст импортирован полностью. В архиве доступна редакция от 09.10.2026.

## Единый интерфейс

`/admin`, `/charters` и `/training` возвращают общую HTML-оболочку. Внутренние переходы обслуживает History API. Если обучение возвращает сообщение о неподготовленном хранилище, проверьте текущую схему PostgreSQL запросом `SELECT to_regclass('rpm_training_attempts');`. Пустой результат означает, что таблица отсутствует в текущем пути поиска. Миграция `002_workspace.sql` применяется вручную.


## Персонализация

Профили администратора и покупателя содержат карточки тем и настройки плотности, анимаций, текста и эффектов. Оформление сохраняется при изменении через `PATCH /api/admin/self/profile` или `PATCH /api/customer/profile`. Тело запроса содержит `theme` и `preferences`. `GET /api/panel/profile`, `GET /api/admin/self` и `GET /api/customer/profile` возвращают сохранённые настройки. Существующее поле `theme` сохраняет совместимость со старыми профилями. Миграция 003 добавляет JSONB-поле настроек, оставляя существующие значения темы.

Тестировать на отдельной PostgreSQL-ветке или через интеграционный тест PGlite. Старые версии приложения могут читать ту же таблицу.

## Приёмка и состав изменений

- Оформление. `appearance.js`, `public/appearance.js`, `public/appearance.css`, `public/theme-catalog.js`, `public/rpm-base.css`, `public/workspace-admin.css`, `public/workspace-admin.js`, `public/index.html`, `private/admin.html`, `private/admin-login.html`, `private/owner.html`, `customer/index.html`, `customer/account.html`.
- Хранение и API. `server.js`, `customer-auth-routes.js`, `workspace-routes.js`, `migrations/003_appearance.sql`. Новый маршрут `POST /api/training/attempts/:id/retry` открывает повторение ошибок принадлежащего пользователю завершённого занятия и сверяет текст нормы с текущей редакцией.
- Документы и обучение. `documents.js`, `private/library.html`, `private/training.html`, `public/workspace-library.js`, `public/workspace-training.js`.
- Проверки. `package.json`, `tests/appearance.test.mjs`, `tests/workspace-documents.test.mjs`, `tests/workspace-integration.test.mjs`.

Проверены восемь импортированных документов. Это «Присяга армии», «Адвокатскаяя Тайна», «Клятва гипокерата», «Устав Универ», «Устав СМИ», «Устав Армия», «Устав Больницы» и «Устав ЦПД». Названия соответствуют каталогу исходников. По каждому документу регрессионный тест проверяет наличие текста и отсутствие терминальной разметки. Отдельный тест проверяет реальные и экранированные ANSI-последовательности, Unicode, номера и абзацы.

Сбой обучения воспроизведён в изолированной базе с отсутствующей таблицей прогресса. PostgreSQL вернул `42P01`. Миграция 002 добавляет эту таблицу. Причина прежней ошибки на Render требует проверки серверного журнала и схемы той базы.

Приёмка охватывает серверные права трёх типов аккаунтов, сохранение профиля и оформления, браузерный путь по уставу ЦПД до результата теста, а также проверку ссылки ЕПК через API. Вызов модели в интеграционном тесте подменяется контролируемым ответом. Для всех коммерческих и служебных разделов, включая заказы, поддержку и операции с резервными копиями, полная браузерная матрица остаётся открытой.
